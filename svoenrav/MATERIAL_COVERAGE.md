# Материалы производственного задания

Статус: код и проверки без развёртывания. Работа с реальной базой ERPNext ещё
требует приёмки. Импорт исходных данных и изменения способа запуска в этот пакет
не входят.

## Рабочий экран

Открыть «Материалы задания» на главной странице или во вкладках мастерской.
Выбрать проведённое открытое Work Order. Кнопка «Проверить» у задания в очереди
или карточке заказа открывает тот же экран с выбранным заданием.

Проверка только читает данные. Она не создаёт резерв, документ, закупку или
складское движение и не меняет очередь.

| Показатель | Значение |
|---|---|
| План | Сумма required_qty строк задания в складских единицах материала |
| Выдано | Сумма transferred_qty по заданию; это не текущий остаток в производстве |
| Осталось выдать | Для обычной передачи: сумма max(required_qty − transferred_qty, 0) по строкам |
| Без отдельной передачи | При skip_transfer: сумма max(required_qty − consumed_qty, 0) по строкам |
| На складе | Bin.actual_qty конкретного материала и склада |
| Все резервы | Bin.reserved_stock: фактические резервы Stock Reservation Entry |
| Резерв задания | Непогашенная часть доступных SRE этого задания именно на показанном складе |
| Свободно | max(actual_qty − reserved_stock, 0) |
| Нехватка | max(остаток к выдаче − доступное с учётом собственного резерва, 0) |

Доступное с собственным резервом ограничивается физическим остатком. Внутри
одного задания одинаковый материал на одном складе объединяется: один и тот же
свободный остаток не засчитывается несколько раз. Перевыдача по одной операции
не уменьшает недовыданную потребность другой операции.

Bin.reserved_qty_for_production, reserved_qty и другие плановые потребности не
вычитаются повторно вместе с reserved_stock. Запланированное поступление не
считается физическим наличием. Единицы автоматически не конвертируются: сравниваются
только одинаковые stock_uom. Склады не объединяются.

## Собственные резервы

Сумма Work Order Item.stock_reserved_qty может включать резервы на разных складах.
Поэтому её нельзя просто прибавить к свободному остатку выбранного склада.

Читаются только доступные SRE с voucher_type = Work Order, voucher_no = выбранное
задание и docstatus = 1. Непогашенная часть = reserved_qty − delivered_qty −
transferred_qty − consumed_qty. Суммы сверяются с каждой строкой задания, затем
группируются по материалу и фактическому складу резервирования. Резерв другого
склада не засчитывается для выдачи с показанного склада.

Если часть резервов недоступна по правам, суммы не сходятся, данные скрыты или
выборка превышает 2000 SRE, положительная обеспеченность не подтверждается.
Если собственных резервов по данным задания нет, учитывается только свободный
остаток после общих резервов. Названия чужих резервирующих документов не выдаются.

## Значение результатов

| Результат | Что означает |
|---|---|
| Покрыто резервами задания | Потребность к выдаче покрывается подтверждёнными резервами на источниках |
| Есть свободный, но не закреплённый остаток | Материала по текущему снимку достаточно, но он доступен и другим заданиям |
| Есть дефицит для выдачи | Не хватает на показанных складах с учётом известных резервов |
| План выдачи выполнен | Материалы по данным задания уже выданы; это не готовность к выпуску |
| Требуется проверка | Не хватает данных либо есть особые условия учёта |

Возвраты, Job Card, полуфабрикаты, технологические потери, отдельное потребление,
давальческое производство, остановленные задания, заблокированные склады и
материалы с партиями/серийными номерами требуют дополнительной проверки полной
формы. Наличие площади кожи не гарантирует, что деталь поместится в конкретный
обрезок. Геометрия, качество и пригодность материала здесь не оцениваются.

Отсутствие доступного Bin не превращается автоматически в ноль: если запись есть,
но не видна, результат неизвестен. Нулевой остаток подставляется только при
фактическом отсутствии записи после проверки доступа к материалу и складу.
Стоимость и цены не запрашиваются и не возвращаются.

## Ограничения

- Это снимок состояния одного задания, а не распределение запасов между всей очередью.
- Два задания могут видеть один свободный незарезервированный остаток. Закрепление
  выполняется штатным механизмом резервирования, а не этой проверкой.
- Чтения не блокируют складские транзакции. Между проверкой и проведением данные
  могут измениться; актуальное проведение остаётся под проверками ERPNext.
- Дефицит на исходном складе не равен количеству к закупке: возможны перемещение,
  замена материала или уточнение задания.
- До 200 строк материалов и 100 сочетаний материал/склад на проверку. При превышении
  предлагается полная форма вместо неполного положительного результата.
- Интерфейс проверен через jsdom с имитацией Frappe; реальная мобильная отрисовка,
  запросы MariaDB и работа прав в ERPNext ещё не подтверждены.

## Приёмка после развёртывания

1. Два заказа на один материал: собственный резерв первого не засчитывается второму.
2. Повторяющийся материал в двух операциях использует один остаток склада.
3. Резерв задания на другом складе не увеличивает доступность исходного склада.
4. Частичная передача, частичный выпуск, возврат и отмена движения.
5. Ограничение пользователя по компании, складу, документам и отдельным полям.
6. Нулевой остаток, отсутствующая запись Bin и скрытая запись Bin.
7. Партии, серийные номера и отрицательные/несогласованные остатки.
8. Изменение остатка другой сессией после проверки, повторное обновление экрана.
