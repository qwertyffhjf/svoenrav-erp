# Готовность SVOENRAV ERP — 04.11.2026

Реализованы меню, короткие операции, очередь, обеспечение материалами, раскрой,
карточка заказа, серверная защита от параллельных черновиков, штатное резервирование,
автоматическая фиксация норм и пакета BOM, аналитические доли оплат, независимый
журнал и рабочие роли. [Поведение и ограничения](ORDER_WORKFLOW.md).

## Подтверждённые проверки

| Проверка | Результат |
|---|---|
| Исходники `tools/svoenrav.py check --source-only` | Успешно |
| Python unittest | 173 теста успешно |
| DOM jsdom | Успешно: переходы, права/ошибки, запоздавшие ответы, двойные нажатия, проверка документа и резервирования |
| Chromium 141 | Успешно: 320, 390, 1280 px; основные экраны без горизонтальной прокрутки страницы |
| Генерация HTML | Проверяется соответствие актуальным шаблону/JS/тестовым данным |
| Синтаксис JS, compileall, git diff --check | Успешно |

Сервер ERP, MariaDB, складские движения и бухгалтерия **не запускались**.
Тесты API используют имитацию Frappe; конкурентный тест использует имитацию
транзакционных блокировок. Chromium проверяет standalone-превью с адаптером,
а не штатные серверные формы. Эти проверки не подтверждают готовность учёта.

## Приёмка после развёртывания

1. Миграция новых DocType и ролей. Назначение реальных пользователей по задачам,
   ограничения компании/склада, отсутствие лишних старых ролей.
2. Два пользователя одновременно сохраняют приёмку, выдачу, выпуск и отгрузку:
   один черновик на источник/операцию; скрытые имена не раскрываются.
3. Подтверждение плана, создание/повтор/ошибка/отмена SRE, сверка строк Work Order
   и Bin; новая конкурентная операция не создаёт избыточный резерв.
4. Проведение Work Order фиксирует нормы и BOM-пакет; ошибка пакета откатывает
   проведение; прогресс допускается, изменение норм требует нового задания.
5. Частичные выдача и выпуск, возвраты, брак, партии/номера и себестоимость.
   Короткий путь сложных сценариев должен останавливаться с пояснением.
6. Смешанные счета, точные доли платежей, отрицательные распределения, валюты,
   отмена доли через 0, изменение native references, права и отсутствие двойного учёта.
7. Журнал без Version: проведение, отмена, db_set, изменение доли; недоступные
   поля/источники не раскрываются, неподтверждённая операция не попадает в учёт.
8. Компьютер и телефон: реальные формы, ввод чисел, ширины 320/390, клавиатура.
9. Резервная копия и восстановление в отдельной базе.

Импорт и постоянное размещение отложены. Архив байтов чертежей, аудит прямого SQL,
планирование смен/закупок и полноценная бухгалтерская сверка остаются отдельными
задачами; они не подменяются текущими экранами.
