# Редактор меню и очередь производства

Статус: реализовано в исходниках, проверено без работающей ERPNext. После обновления
требуется миграция сайта и проверка на реальных пользователях и документах.

## Меню без JSON

1. На стартовой странице открыть «Настройки» (SVOENRAV Settings).
2. Нажать «Перенести сохранённое меню в таблицу» либо «Заполнить стандартным меню».
3. Проверить строки: название, документ, способ открытия, раздел, видимость.
4. При выборе короткой формы тип документа и способ открытия подставляются автоматически.
5. Поменять порядок строк, убрать флажок у ненужных кнопок и сохранить настройки.

Кнопка копирования берёт **сохранённое**, а не текущее несохранённое меню. Перед
заменой строк запрашивается подтверждение. Копирование само настройки не сохраняет.
При ошибке загрузки таблица остаётся прежней. Скрытые строки сохранённой таблицы
также переносятся, служебные метаданные дочерних документов не выдаются.

Источник меню выбирается явно: «JSON» или «Таблица». Для существующей установки
сохраняется JSON, автоматического переключения нет. Перейти обратно можно в любое
время: прежний JSON не стирается. В табличном режиме пустая таблица означает
отсутствие кнопок, а не возврат стандартного меню. Неактивный источник не используется.

До 30 строк. Порядок сохраняется внутри соответствующего раздела страницы:
быстрые действия располагаются перед обычными разделами. Настройки доступны
владельцу с правами System Manager; видимость кнопки не даёт прав на документ.
Сервер продолжает проверять права чтения/создания, типы операций и допустимые параметры.
Произвольные ссылки, скрипты и проведение документов через настройки меню запрещены.

## Очередь производства

Открыть «Очередь производства» на главной странице или вкладку с тем же названием
на `/desk/svoenrav-workshop`. Читаются только доступные пользователю проведённые
Work Order, кроме завершённых, закрытых и отменённых. Остановленные задания видны.

Порядок всей доступной очереди:

1. Задания с ручным приоритетом — раньше заданий без него.
2. Меньшее положительное число приоритета — раньше.
3. При равном приоритете — ближайший срок; задания без срока идут после датированных.
4. Затем дата создания и номер документа для устойчивого порядка.

Объём партии, длительность и заполнение смены в сортировке не участвуют.
Очередь не распределяет задания по людям и станкам и не рассчитывает мощность.

Для изменения открыть «Настроить приоритеты и паузы» и заполнить таблицу
SVOENRAV Production Settings. Право изменения — System Manager. Приоритет:
целое 1–999999; 0 или пустое поле — без ручного приоритета. Одинаковые числа
допускаются, тогда действует сортировка по срокам. Каждое задание в таблице
может встречаться только один раз. Проверяется право чтения связанного задания.
Удаление строки сбрасывает ручной приоритет и паузу этого задания.

Пауза планирования требует причины. Она не меняет штатный статус Work Order,
не останавливает документы ERPNext и не удаляет задание из очереди. Статус Stopped
показывается отдельно; если причина штатной остановки не внесена в примечание,
система её не выдумывает. Просрочка определяется по сроку относительно текущей
даты сайта ERPNext; отсутствие срока не считается просрочкой.

Показываются страницы по 50 заданий **после общей сортировки**. При более чем
1000 доступных открытых заданий страница выдаёт пояснение вместо неполной очереди.
В настройках также до 1000 строк; старые приоритеты закрытых заданий автоматически
не удаляются. Владелец может убрать их вручную.

Обычным сотрудникам выдаются только приоритеты и причины доступных им заданий.
Полная таблица настроек доступна только пользователям с правами на неё. В очереди
не показываются скрытые задания даже тогда, когда они есть в настройках владельца.

Блок «Ближайшие сроки» на главной странице остаётся обзором по срокам и явно
ссылается на полную очередь с ручными приоритетами.

## Проверка после развёртывания

- Сохранение и возврат между JSON и таблицей, скрытие и изменение порядка кнопок.
- Загрузка новой Single-формы и дочерних таблиц после миграции.
- Подстановка параметров короткой формы и изменение собственных кнопок.
- Приоритет позднего крупного заказа выше раннего малого и обратный пример.
- Равные приоритеты, пустые сроки, остановка и пауза с причиной.
- Права по компаниям и конкретным заданиям; отсутствие чужих причин в выдаче API.
- Переход между страницами, обновление очереди и работа на телефоне.
- Конкурирующее редактирование настроек: используется штатное сохранение Frappe,
  отдельного механизма объединения параллельных правок не добавлено.
